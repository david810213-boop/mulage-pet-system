# 既有會員資料匯入與 LINE 自助認領——完整流程（2026-09-07 修正版）

**更新原因**：CSV 匯入功能原本無條件假設檔案是 UTF-8 編碼，遇到 Windows 存出的 Big5 編碼檔案時，中文欄位（家長姓名、寵物名字、物種、品種、備註）會靜默變成無法辨識的亂碼字元，導致寵物資料整批匯入失敗，但因為電話、金額都是純數字不受影響，容易誤判成「只有部分功能壞掉」。這份文件是修正後的完整流程，取代舊版《功能總覽與測試手冊》七之一節的說明。

---

## 一、整體流程總覽

分兩個階段，中間銜接靠「電話號碼」：

```
階段一：店家後台批次匯入                    階段二：老客戶 LINE 自助認領
┌─────────────────────┐                ┌─────────────────────┐
│ 店家上傳 CSV          │                │ 老客戶加 LINE 好友    │
│ → 系統依電話號碼      │   電話號碼配對  │ → 進「新客報到」頁     │
│   分組建立會員+寵物   │ ─────────────→ │ → 輸入電話號碼認領     │
│   資料（骨架資料）     │                │ → 姓名/寵物資料整批   │
└─────────────────────┘                │   帶到這個 LINE 帳號  │
                                        └─────────────────────┘
```

在階段一完成之前，這些會員資料只存在後台，沒有對應的 LINE 帳號；階段二是老客戶自己完成「認領」，把後台骨架資料跟自己的 LINE 帳號綁在一起。

---

## 二、階段一：店家後台 CSV 批次匯入

### 2-1　準備 CSV 檔案

**編碼需求（2026-09-07 起放寬）**：系統現在會**自動偵測檔案編碼**，依序嘗試 UTF-8 → Big5 → GBK，三種常見編碼都能正確解析中文，**不再強制要求存成 UTF-8**。也就是說：

- 用 Windows 記事本/Excel 存出的一般 CSV（通常是 Big5）→ 現在可以直接上傳，不用再另外轉檔
- 用 Google 試算表或新版 Excel 存出的 UTF-8 CSV → 一樣可以直接上傳
- 兩種都上傳失敗才會退回寬鬆模式，並在畫面/log 提示可能有亂碼

> ⏰ 雖然現在容錯範圍變大，**建議還是優先使用 UTF-8**（用 Google 試算表匯出最保險），自動偵測是保護網，不是鼓勵隨便存檔。

### 2-2　三種匯入類型

| 匯入類型 | 內容 | 重複上傳會怎樣 |
| :---- | :---- | :---- |
| 會員與寵物資料 | 電話、姓名、寵物名字/物種/品種/體重/年齡等 | 電話已存在的**整組跳過**，不會重複建立 |
| 消費紀錄 | 歷史消費金額、日期、備註等 | 沒有防重複機制，同一份請勿重複上傳 |
| 儲值餘額 | 會員現有的儲值金額 | ⚠️ **用「加總」方式**，同一份重複上傳會讓餘額被重複加算 |

### 2-3　上傳與結果確認（畫面行為，2026-09-07 更新）

1. 進「會員管理 → 既有會員資料匯入」，選擇對應類型的 CSV 上傳
2. 系統依序處理每一列，**逐列驗證，不是整批成功或整批失敗**——一列資料有問題只會擋下那一列，其他正常列照常匯入
3. 上傳完成後畫面會顯示結果，分兩種情況：
   - ✅ 正常匯入的筆數
   - ⚠️ 格式錯誤清單（`result.rowErrors`）：列出**哪一列、哪個欄位**出了問題

### 2-4　常見錯誤訊息怎麼看（2026-09-07 更新，訊息更明確）

| 錯誤訊息範例 | 代表的意思 | 怎麼處理 |
| :---- | :---- | :---- |
| 第 3 列寵物資料解析失敗：疑似編碼異常，品種欄位內含無法辨識的字元，請將原始 CSV 另存成 UTF-8 或 Big5 後重新上傳 | 這一列有中文欄位無法正確解碼（三種編碼都試過還是失敗，落到寬鬆模式產生亂碼字元） | 打開原始檔案，確認第 3 列的品種欄位有沒有特殊符號或損壞字元；用 Google 試算表重新存一次 UTF-8 版本再上傳 |
| 第 5 列寵物資料解析失敗：品種欄位為空 | 這一列品種欄位是空白 | 補上品種資料再重新上傳這一列（或忽略，之後請顧客自己在 LINE 補） |
| 第 8 列寵物資料解析失敗：體重欄位格式錯誤：abc | 體重欄位填了非數字內容 | 修正成數字格式（可以有小數點） |

> 這些錯誤訊息都是**匯入資料庫之前**就攔下來的，不會因為某一列壞掉就讓整份檔案的其他正常資料一起匯入失敗。

### 2-5　後台 log 會多記錄什麼（2026-09-07 新增，僅供工程排查用，店家平常不用看）

每次匯入後台 log 會印出偵測到的編碼，例如：
```
📄 [會員資料匯入] 偵測到 CSV 檔案編碼：Big5
```
如果三種編碼都失敗、退回寬鬆模式，會印 WARN 等級提醒可能有亂碼殘留。這個記錄只在伺服器後台看得到，不影響店家操作畫面。

## 三、階段二：老客戶 LINE 自助認領

### 3-1　前置作業：店家主動觸及老客戶

CSV 匯入只是把資料放進系統，老客戶自己還不知道、也還沒綁定 LINE。店家需要：

1. 用 LINE 官方帳號發**群發訊息**，或設定**圖文選單**，附上連結引導老客戶點進「新客報到」頁面
2. 訊息內容建議提醒：「請直接輸入您的手機號碼，即可自動帶入您原有的毛孩資料，不用重新填寫」

### 3-2　顧客端操作流程

1. 老客戶加官方帳號好友，或點群發訊息裡的連結，進入「新客報到」頁面
2. 看到「輸入電話號碼認領資料」欄位（⚠️ 這個欄位**只在「填寫個人資料」跟「新增毛孩檔案」兩個步驟都還沒完成時**才會出現——如果這支 LINE 帳號已經填過資料或已經有毛孩，就不會再顯示這個欄位）
3. 輸入電話號碼，系統比對後台既有資料
4. 比對成功：姓名、寵物資料（名字、物種、品種、體重、年齡等）**整批自動帶入**這支 LINE 帳號，不用重新填寫
5. 比對失敗（電話號碼不在系統裡）：照一般新客戶流程手動填寫資料

### 3-3　認領後，資料歸屬怎麼變化

- 認領完成後，這筆會員資料就正式跟這支 LINE 帳號綁定
- 消費紀錄、儲值餘額（如果階段一有一併匯入）也會一起連動到這個帳號，顧客在「錢包」頁面就能看到餘額、在消費紀錄裡看到歷史紀錄
- 如果店家事後手動調整過這筆會員資料（例如在「會員信息」頁改了姓名），顧客認領後看到的會是最新版本

## 四、給店家的操作檢查清單

匯入前：
- [ ] CSV 檔案盡量存成 UTF-8（Google 試算表匯出最快），但存成一般 Big5 現在也能自動辨識
- [ ] 確認電話號碼欄位格式一致（不要有些加國碼、有些沒加）
- [ ] 儲值餘額 CSV 確認這份資料**沒有上傳過**，避免餘額被重複加總

匯入後：
- [ ] 查看畫面上的「格式錯誤」清單，有沒有列出任何一列有問題
- [ ] 如果有「疑似編碼異常」的錯誤，優先處理這幾列（代表這幾列的資料目前完全沒有進到系統裡）
- [ ] 抽查幾筆匯入成功的會員，進「會員信息」確認寵物資料（尤其品種、毛長）有沒有正確帶入，不是只看電話跟姓名

認領推廣：
- [ ] 用 LINE 官方帳號發群發訊息或設定圖文選單，引導老客戶進「新客報到」輸入電話號碼
- [ ] 抽查幾位認領後的老客戶帳號，確認寵物資料、儲值餘額都正確連動

## 五、常見問答（更新版）

**Q：以後 CSV 一定要存成 UTF-8 才能用嗎？**
A：不用了。系統現在會自動嘗試 UTF-8、Big5、GBK 三種編碼，一般 Windows 存出的 Big5 CSV 可以直接上傳。但還是建議優先用 UTF-8（例如透過 Google 試算表匯出），比較不會遇到少見的編碼組合。

**Q：上傳後畫面說某幾列「疑似編碼異常」，這幾列的資料是不是就永遠救不回來了？**
A：不是。這只代表**這次上傳**這幾列沒有成功匯入，資料本身還在你原本的 CSV 檔案裡。把原始檔案用 Google 試算表或記事本重新存一次 UTF-8 格式，只保留這幾列有問題的資料，再重新上傳一次即可。

**Q：畫面顯示「第 5 列寵物資料解析失敗」，這一列之後的資料還會繼續匯入嗎？**
A：會。現在是逐列驗證，一列有問題只會擋下那一列，不會影響其他列，不用整份重傳。

**Q：儲值餘額不小心上傳兩次，餘額被多算了怎麼辦？**
A：儲值餘額匯入是用加總的，重複上傳會讓餘額變兩倍。目前沒有自動扣回機制，需要請工程協助手動修正該會員的錢包餘額，之後上傳前務必先確認這份資料沒上傳過。

**Q：老客戶在「新客報到」頁找不到「輸入電話號碼認領」的欄位？**
A：這個欄位只在顧客的 LINE 帳號還沒填過個人資料、也還沒新增過毛孩檔案時才會出現。如果對方已經手動填過資料（例如自己先加好友填了新客資料），就不會再顯示這個欄位，需要請工程協助手動合併資料。
