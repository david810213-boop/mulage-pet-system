# 0009 預約訂金：以「同一會員同一天」為一組計算，份額記在每筆預約上，人工核帳

## 背景
店家公告《預約須知｜訂金及取消規範》：線上只開放三日後的時段；同一天預約兩位以上、或首次體驗的大型犬（23 公斤以上）需預付訂金（大型犬 $1,000／位，其他每位 $500，所以 2 位 $1,000、3 位 $1,500……）；儲值金會員免付。送出後 24 小時內付款，逾期自動取消。取消時依距離預約開始的時間退款：72 小時以上退全額、72 小時內退一半、24 小時內與未到店不退；店家因素取消全額退。已付訂金的預約可在 72 小時前改期一次，訂金跟著走。訂金在服務當天結帳時折抵。

系統原本一次只預約一隻毛孩，「同一天兩位以上」會跨好幾筆預約、甚至分好幾次送出。

## 決策
- **一組＝同一會員同一天的有效預約**（不含已取消）。每筆預約記自己的訂金份額 `depositShare` 與已收金額 `depositPaid`，規則集中在 `DepositPolicy`（純計算，`DepositPolicyTest` 驗證）。份額記在單筆上，部分取消、退款、改期、結帳折抵都能逐筆處理，不必回頭分攤一筆總額。
- **新預約送出後若當天還有沒付清的金額，這筆新預約改為「待付訂金」**（新增狀態 `AWAITING_DEPOSIT`，佔用時段名額）並設定付款期限。當天原本的預約維持原狀態，它們新增的份額由這次付款一起收；如果新預約逾期被取消，重新計算後原本的預約又不需要訂金，狀態也不用還原。
- **付清（或店員免收）後，當天需要訂金、還在待付訂金或待確認的預約一律轉為已確認**並通知顧客，符合「收到訂金後自動改為預約成功」。店員不能對待付訂金的預約直接按確認。
- **首次大型犬**在建立預約時判斷（沒有已付款紀錄＋體重 ≥ 23 公斤），存成 `depositLargeFirstVisit`，之後重算份額不必再查消費紀錄。
- **儲值金會員**以錢包餘額大於 0 判斷，整天免收；店員免收（`depositWaived`）也是整天免收，原因寫入操作紀錄。
- **人工核帳**：顧客在 LIFF 填匯款帳號後五碼回報（`DepositPayment`，金額由系統依當下未付清金額決定），店員在手機版「訂金核帳」確認或駁回。確認與駁回先鎖住該筆的狀態（同 0008）。之後接金流的 ATM 虛擬帳號時，入帳通知只要呼叫同一個 `confirmPayment` 流程，模型不用改。
- **逾期排程**每 10 分鐘取消付款期限已過的待付訂金預約；顧客在期限內已回報、店家還沒核帳的不取消。
- **取消**時把保留的訂金拆成「應退」與「不退」，應退的記為待退款，店員匯款後標記完成（ATM 轉帳無法原路退回）。已付訂金的預約顧客不能在 LIFF 自行取消，需透過官方 LINE。顧客自行取消（未付訂金的）會推播通知店家。
- **結帳折抵**：`Transaction.finalAmount` 仍是完整服務金額（營收報表不受影響），另記 `depositApplied`；當下實際收取 `finalAmount - depositApplied`，儲值金也只扣這個差額。訂金多於應付金額時差額轉為待退款。
- **並發**：改寫份額前先鎖會員列，再以 `SELECT ... FOR UPDATE` 讀取當天的預約。MySQL 可重複讀下一般查詢讀的是交易開始時的快照，同一會員同時送出兩筆時會漏算對方剛提交的那一筆。
- `appointments.status` 改為 VARCHAR（V19 遷移），避免既有資料表的原生 ENUM 無法寫入新狀態（同 0006）。

## 後果
- 營收報表以服務金額計算，被沒收（不退）的訂金目前沒有計入營收報表，需要時再另外加總 `depositForfeitedAmount`。
- 改期到另一天時，訂金跟著預約走，兩天各自重新計算份額，但不會自動把預約改回待付訂金；新日期若因此需要補訂金，由店員處理。
- 結帳後又退款時，折抵的訂金回到預約上；若當初結帳產生了「差額待退款」且尚未退，需由店員自行調整。
