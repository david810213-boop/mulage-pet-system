# 0010 慕馬 AI 小助手：Claude Haiku 加唯讀工具，題數與預算雙重上限，按鈕只來自白名單

## 背景
顧客常問的問題（營業時間、價目、哪天有空位、訂金怎麼算、自己的預約與儲值金）答案都在系統或店家公告裡，但目前只能透過官方 LINE 由店員人工回覆。店家希望在 LIFF 會員頁加一個 AI 小助手「慕馬」，用自然的語氣回答，答不了的轉給真人。限制：每月預算 NT$600（約 US$19）；不能替顧客預約、取消或付款；顧客資料不能外洩給其他顧客。

## 決策
- **模型**：Claude Haiku（`claude-haiku-5-5`，環境變數 `ASSISTANT_MODEL` 可換）。回答限 1～3 句、80 字內，`max_tokens` 400。推論地區維持預設（global），指定美國會多收 10%。
- **知識來源分兩種**：
  - 不常變的規則（店家資訊、預約與訂金規範、折扣、儲值方案、慕馬不能做的事）寫在 `src/main/resources/assistant/knowledge.md`，和角色設定一起放在 system prompt 的第一段並標記快取（prompt caching），之後的提問只付快取讀取的價格（約原價 1/10）。
  - 會變的資料（顧客自己的預約、訂金、儲值金、毛孩、空位、可預約項目與價錢、公休日）由模型呼叫工具（`AssistantTools`）即時查詢。工具只包裝既有的 service 方法、全部唯讀，參數裡沒有會員 id，一律以登入者查詢，模型無法查到別人的資料。
  - 現在時間、顧客稱呼、所在頁面放在 system prompt 第二段（不快取）。
- **按鈕**：模型只能在回答裡寫 `[[按鈕:代碼]]` 標記，由 `AssistantActions` 對照白名單換成固定網址（預約、我的預約、匯款資訊、錢包、毛孩、會員資料、契約、官方 LINE），最多 2 個。模型寫的網址或不在白名單的代碼一律丟棄，避免被誘導產生釣魚連結。
- **真人客服**：不確定時加官方 LINE 按鈕，由店員在 LINE 官方帳號人工回覆；系統不另做轉接。
- **成本上限（兩層）**：
  - 每人每天 20 題（`ASSISTANT_DAILY_LIMIT`），只計算有實際呼叫模型的回答；呼叫失敗、達上限的備用回覆不扣題數。
  - 本月累計花費達預算（`ASSISTANT_MONTHLY_BUDGET_USD`）的 95% 就不再呼叫模型，改回覆請聯絡店家。花費依每次回應的 token 用量與單價換算後存在每則對話上（`assistant_messages.cost_usd`），Anthropic Console 另設同額的 spend limit 當第二道防線。
  - 對話歷史只帶 2 小時內最近 6 則；問題限 200 字。
- **開關**：`ASSISTANT_ENABLED`（預設關閉）一鍵停用；`ASSISTANT_TESTERS` 填會員 id 清單時只開放給這些人，清空即開放全部會員。前端先呼叫 `/api/me/assistant/quota`，沒開放就完全不顯示。
- **不包在資料庫交易裡**：呼叫模型可能要好幾秒，`AssistantService.ask` 不加 `@Transactional`，避免長時間占住資料庫連線；工具呼叫各自走原本 service 的交易。
- **失敗處理**：API 逾時（連線 5 秒、讀取 30 秒）、金鑰未設定或回傳錯誤時，回覆固定的「慕馬現在有點忙」加官方 LINE 按鈕，不影響頁面其他功能。
- **紀錄**：每則提問與回答都存在 `assistant_messages`（含頁面、token 用量、花費、是否為備用回覆）。店長在後台「慕馬對話紀錄」看最近 14 天的對話、本月花費與預算，發現答錯就修改知識文件。
- **前端**：`/liff/assistant.js` 由各 LIFF 頁面引用，讀取頁面已有的 `jwtToken`，不另外登入。按鈕位置存在 localStorage、對話存在 sessionStorage（都包 try/catch，讀不到就用預設）。

## 後果
- 知識文件改了要重新部署才生效；店家的公告或規則改變時要記得同步修改 `knowledge.md`。
- 模型仍可能答錯，所以知識文件與 system prompt 都要求「不確定就轉真人」，回答不做承諾（例如不保證一定有空位），並由店長定期抽查對話紀錄。
- 對話內容（含顧客的問題）會送到 Anthropic API；API 預設不拿來訓練模型。告知放在慕馬面板的歡迎畫面（傳送給 AI 服務、不用於訓練、請勿輸入敏感資料），不寫進定型化契約，契約改版不必綁著慕馬。
- 預算用完時當月剩下的天數慕馬只會請顧客聯絡店家；若常發生，再評估提高預算或降低每日題數。
- 測試用假的 `LlmClient`（`AssistantServiceTest`），CI 不會呼叫真的 API；模型實際回答的品質要在測試名單階段人工檢查。
